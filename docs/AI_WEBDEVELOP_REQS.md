# 君册财税 AI 初诊网站  
# 前期需求资料准备清单 v1

## 一、文档目的

本清单用于在开发「君册财税 AI 初诊 / AI 检测网站」前，向纪姐系统性收集业务资料。

AI 初诊不是单纯接入一个大模型就能准确判断。它真正需要的是把君册现有的财税经验、诊断规则、服务判断标准、风险话术、报告模板和人工复核流程整理成结构化资料。  
资料越完整，AI 初诊输出越接近君册自己的顾问判断；资料不完整，系统只能先做问卷收集和初步报告，无法做准确诊断。

本清单不要求一次性全部提供。可以先按优先级分批准备。

# 二、AI 初诊与当前小程序的关系

## 2.1 当前小程序已有数据可复用

目前君册内部管理小程序已经沉淀了一部分客户基础信息。这些信息后续可以直接作为 AI 初诊的输入数据，减少重复填写。

| 小程序已有字段 | AI 初诊用途 |
|---|---|
| 企业名称 companyName | 报告抬头、客户识别 |
| 行业 industry | 判断行业相关风险，如食品、运输、进出口等 |
| 注册时间 registerDate | 判断企业经营年限，新公司与老公司风险不同 |
| 税务类型 taxType | 小规模 / 一般纳税人的检查规则不同 |
| 区域 region | 后续可用于区域性政策差异判断 |
| 年流水 annualRevenue | 判断企业规模、税负风险、客户价值 |
| 人员数 staffCount | 判断社保、个税、工资合规 |
| 公司类型 companyType | 一人公司、多股东、个体户的风险不同 |
| 客户类别 customerCategory | 新用户 / 代理户判断 |
| 客户分层 tier | 结合服务价值、风险等级、客户管理优先级 |
| 生命周期阶段 lifecycleStage | 判断客户当前处于填单、办件、维护还是出库状态 |
| 服务类型 serviceType | 后续用于服务推荐，如注册、代理记账、食品证、合规项目等 |

## 2.2 当前小程序没有、必须由客户补充的资料

以下内容目前小程序里没有，必须由纪姐提供，否则 AI 初诊无法做出有君册特色的判断。

| 资料类别 | 为什么必须提供 |
|---|---|
| 九维 / 四维诊断规则 | 决定 AI 到底从哪些方面检查企业 |
| 每个维度的检查项 | 决定每一维具体问什么、查什么 |
| 风险等级标准 | 决定低风险、中风险、高风险怎么判 |
| 常见风险场景 | 决定 AI 是否能识别实际财税问题 |
| 标准建议话术 | 决定 AI 输出是否像君册顾问 |
| 服务推荐规则 | 决定发现问题后推荐什么业务 |
| 初诊报告模板 | 决定最终报告长什么样 |
| 人工复核规则 | 决定哪些报告必须人工确认 |
| 禁用话术 / 合规边界 | 防止 AI 说错话、承诺过度或形成风险 |

# 五、九维 / 四维诊断规则

九维 / 四维是 AI 初诊的核心规则体系。  
如果这部分不明确，AI 只能做普通问卷和泛泛建议，不能形成君册自己的诊断逻辑。

## 5.1 需要纪姐明确九维是什么

请纪姐直接列出：

1. 第一维：__________
2. 第二维：__________
3. 第三维：__________
4. 第四维：__________
5. 第五维：__________
6. 第六维：__________
7. 第七维：__________
8. 第八维：__________
9. 第九维：__________

如果目前还没有固定名称，可以先按实际工作经验回答：

- 平时给客户做企业体检时，一般检查哪些方面？
- 哪些方面最容易出问题？
- 哪些方面最能体现君册专业判断？

## 5.2 需要纪姐明确四维是什么

请纪姐直接列出：

1. 第一维：__________
2. 第二维：__________
3. 第三维：__________
4. 第四维：__________

并说明四维和九维的关系：

- 四维和九维是两个不同模型？

## 5.3 每一维需要提供的内容

每一个维度都需要按照以下格式整理：

| 内容 | 需要提供 |
|---|---|
| 维度名称 | 例如：税务维度 |
| 检查目标 | 这一维主要判断什么 |
| 检查项 | 具体问哪些问题 |
| 正常标准 | 什么情况算正常 |
| 轻微风险 | 什么情况算轻微风险 |
| 中风险 | 什么情况算中风险 |
| 高风险 | 什么情况算高风险 |
| 是否必须人工复核 | 是 / 否 |
| 对应建议 | 出现问题时怎么建议客户 |
| 推荐服务 | 对应君册哪项服务 |

## 5.4 每个检查项需要的判断规则

以"长期零申报"为例，需要补齐：

| 项目 | 示例 |
|---|---|
| 检查项 | 是否长期零申报 |
| 触发条件 | 连续几个月零申报 |
| 正常 | 偶尔无收入零申报 |
| 低风险 | 连续 1-2 个月零申报 |
| 中风险 | 连续 3-6 个月零申报 |
| 高风险 | 连续 6 个月以上且有实际经营 |
| 建议 | 建议做账务合规检查 |
| 是否推荐服务 | 代理记账 / 合规项目 |
| 是否人工复核 | 连续 6 个月以上建议人工复核 |

所有检查项都建议按这个格式提供。

# 六、风险等级规则

AI 初诊报告最终必须给出风险等级，因此需要纪姐明确风险分层。

## 6.1 总体风险等级

建议至少分为：

| 风险等级 | 需要纪姐定义 |
|---|---|
| 低风险 | 什么情况算低风险 |
| 中风险 | 什么情况算中风险 |
| 高风险 | 什么情况算高风险 |
| 待人工复核 | 什么情况不让 AI 直接判断 |

## 6.2 需要明确的问题

1. 什么情况直接判高风险？
2. 什么情况只能提示关注，不能判风险？
3. 多个中风险叠加，是否升级为高风险？
4. 一个高风险是否直接决定总报告为高风险？
5. 信息不完整时，是输出"无法判断"还是"待补充资料"？
6. 客户填写内容明显矛盾时，怎么处理？
7. 哪些结论必须人工确认后才能显示给客户？
8. 风险等级是否需要打分？
9. 是否需要红 / 黄 / 绿颜色展示？
10. 是否需要给每个维度单独风险等级？

## 6.3 风险叠加规则

需要纪姐确认一种规则：

| 方案 | 说明 |
|---|---|
| 取最高风险 | 只要有一个高风险，总体就是高风险 |
| 分数累加 | 每个风险有分值，总分决定等级 |
| 关键项优先 | 某些关键项一票否决 |
| 人工判断 | AI 只列问题，风险等级人工确认 |

第一版建议先采用"关键项优先 + 总体风险等级"的简单方式，但最终由纪姐确认。

## 2. 核心检查维度

不要求九维 / 四维一次完整。

- 税务

最终以纪姐实际规则为准。

## 3. 每个维度的检查项

- 是否有欠税
- 是否有处罚
- 是否申报收入异常

## 4. 风险等级标准

至少给低 / 中 / 高三档判断标准。  
不需要一开始完美，但必须能让 AI 初步分类。

- 企业概况
- 风险总览
- 风险明细
- 整改建议
- 推荐服务
- 免责声明

每个场景写清：

- 怎么识别
- 属于什么风险
- 怎么提醒客户

拿到这 6 样，就可以开始设计第一版 AI 初诊网站。

# 十八、我的整合判断

Claude Code 的分析偏开发落地，重点在"需要什么资料才能建库、建表、写规则、出报告"。这个方向正确。

补充后的需求清单需要更强调三个点：

1. 资料不能只问"有没有九维四维"，必须问清每一维的检查项、判断标准、风险等级、建议话术。
2. 报告模板和禁用话术必须提前要，否则 AI 很容易输出不合适的结论。
3. 第一版不要追求完整智能化，先做"问卷 + 规则初筛 + 报告 + 人工复核"，后续再做后台规则管理和复杂 AI 问诊。

最终建议：先向纪姐索要第一批资料。第一批资料回来后，就可以开始做 AI 初诊网站的产品原型和技术方案。
