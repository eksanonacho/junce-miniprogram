# FRONTEND_HANDOFF.md — 前端交接文档

> **这个文件是给谁看的**:负责前端开发的同学。
> **什么时候用**:开始做前端、或前后端联调遇到问题时。
> **解决什么问题**:让你不用理解后端代码,也能独立开发客户模块前端,并和后端无缝联调。
> 最后更新:2026-06-03。

---

## 一、项目背景

这是给「青岛君册财税」(一家财税服务公司)开发的**内部管理小程序**。给公司内部员工用的,管理客户从进来到服务完成的全过程。

第一期要做的模块:客户管理 → 办件流转 → 费用 → 任务 → 看板。
**你这批先只做"客户管理"模块的前端页面。** 其他模块后续再排。

后端(数据库、登录、客户接口)已经做好并测试通过了,你只管前端。

---

## 二、前端技术栈

- **uni-app(Vue3 写法)**,最终发布到微信小程序。
- **调试阶段先以 H5 为主**(浏览器里跑,快、好调),后续再适配微信小程序、用微信开发者工具预览。
- 状态管理用 Pinia(存登录 token、用户信息)。
- 网络请求用 `uni.request()`,统一封装一个请求方法(自动带 token、统一处理错误)。
- UI 简洁清爽即可,这批不追求花哨,先把功能跑通、跳转顺畅。

## 四、页面说明

### 4.1 登录页
- **作用**:用户输入账号密码登录,拿到 token。
- **用户**:公司各角色员工(商务、业务、会计、主管、总务、老板)。
- **表单字段**:用户名(username)、密码(password)。
- **调用接口**:`POST /auth/login`,body:`{"username":"...","password":"..."}`
- **成功后**:保存返回的 accessToken 和 user 信息(用 uni.setStorageSync),跳转到客户列表页(或首页)。
- **错误提示**:账号或密码错时,后端返回 401 + "用户名或密码错误",前端弹 toast 提示该消息。
- **测试账号**:`shangwu / 123456`(商务岗,能建客户)。其他角色账号见后端提供的账号列表。

### 4.2 客户填单页(新建客户)
- **作用**:主理人(商务)谈成交后,填客户企业信息,提交新建。
- **用户**:商务岗。
- **表单字段**(详见第六节字段表):
  - 企业名称(必填)、客户分类(必填:新用户/代理户)
  - 行业、区域、年流水、人员数、公司类型、客户分层(选填)
- **调用接口**:`POST /customers`,body 为上述字段。
- **注意**:不要传 ownerId(后端自动取当前登录人)、不要传 lifecycleStage(后端默认"填单")。
- **成功后**:提示"提交成功",跳转回客户列表页(列表能看到新建的客户)。
- **错误提示**:必填项没填,前端先做校验拦截;后端返回错误时弹 toast 显示后端的 message。

### 4.3 客户列表页
- **作用**:列出所有客户,支持筛选和搜索。
- **用户**:各角色(本批先不做"会计只看自己客户"的细控,所有登录用户都能看列表)。
- **功能**:
  - 显示客户列表(公司名、分类、分层、生命周期状态等)
  - 按分层筛选(tier:VIP/优质/中低/零申报)
  - 按公司名搜索(keyword)
- **调用接口**:`GET /customers`,可带 query:`?tier=VIP&keyword=建筑&lifecycleStage=填单`(都可选)
- **交互**:点某个客户 → 跳转客户详情页(带上客户 id)。
- **错误提示**:列表加载失败弹 toast。

### 4.4 客户详情页
- **作用**:看一个客户的完整信息。
- **用户**:各角色。
- **调用接口**:`GET /customers/:id`(id 从列表页传过来)。
- **交互**:页面上有"编辑"按钮 → 进入编辑态(或跳编辑页)。
- **错误提示**:加载失败弹 toast。

### 4.5 客户编辑页
- **作用**:修改客户信息。
- **用户**:商务岗/主理人。
- **调用接口**:`PATCH /customers/:id`,body 只传**要改的字段**(没传的后端保持不变)。
- **成功后**:提示"保存成功",返回详情页(显示更新后的信息)。
- **错误提示**:弹 toast 显示后端 message。

## 五、登录与 token

1. **登录后保存 token**:`POST /auth/login` 成功后,返回里有 `accessToken`,用 `uni.setStorageSync('token', accessToken)` 存起来,同时存 user 信息。
2. **后续每个请求带 token**:在请求 header 里加 `Authorization: Bearer <token>`。建议封装在统一的 request 方法里,自动加,不用每次手写。
3. **token 失效处理**:如果某个请求返回 401(token 过期或无效),前端清掉本地 token,跳回登录页,提示"登录已过期,请重新登录"。

```
// 伪代码,封装请求
function request(options) {
  const token = uni.getStorageSync('token')
  options.header = { ...options.header, 'Authorization': 'Bearer ' + token }
  // 401 时跳登录页
}
```

## 六、客户字段表(填单/编辑用)

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| companyName | 文本 | 是 | 企业名称 |
| customerCategory | 下拉 | 是 | 新用户 / 代理户 |
| industry | 文本 | 否 | 行业 |
| registerDate | 日期 | 否 | 注册时间,ISO 格式如 "2024-01-01" |
| taxType | 文本 | 否 | 税务类型 |
| region | 文本 | 否 | 区域 |
| annualRevenue | 数字 | 否 | 年流水(元),最多2位小数 |
| staffCount | 整数 | 否 | 人员数 |
| companyType | 下拉 | 否 | 一人公司 / 多股东 / 个体户 |
| tier | 下拉 | 否 | VIP / 优质 / 中低 / 零申报 |

**枚举值速查**:
- customerCategory:`新用户`、`代理户`
- companyType:`一人公司`、`多股东`、`个体户`
- tier:`VIP`、`优质`、`中低`、`零申报`
- lifecycleStage(后端控制,前端不用传):`填单`、`办件中`、`办结`、`维护中`、`出库`

**不要传的字段**:ownerId(后端自动取登录人)、lifecycleStage(后端默认"填单")。

## 七、联调方式(重点,不看会卡住)

### 核心认知
**你电脑上的 `localhost` 指向的是你自己的电脑,不是后端所在的电脑。** 所以直接写 `localhost:3000` 你连不到后端。

### 解决办法(开工时后端会给你具体地址)
- **方案 A(同一 WiFi)**:后端给你一个局域网 IP,比如 `http://192.168.x.x:3000`,你把 API 地址填这个。
- **方案 B(不同网络)**:后端用内网穿透(ngrok/cpolar)给你一个公网网址,你填那个。

### 必须做:API Base URL 统一配置
把后端地址配成**一个变量**(比如 `const BASE_URL = 'http://192.168.x.x:3000'`),所有请求都用它拼接。这样切换地址只改一处。**不要把地址写死在每个请求里。**

### 如果遇到 502 Bad Gateway
这是本机代理/VPN 拦截了请求。用 curl 测试时加 `--noproxy "*"`;浏览器调试时,在代理软件里开启"绕过局域网/本地地址",或临时关掉代理。

### 自测用 curl(验证后端是否通)
```
curl -i --noproxy "*" -X POST http://<后端地址>/auth/login \
  -H "Content-Type: application/json" \
  -d '{"username":"shangwu","password":"123456"}'
```
看到返回 200 + token,说明能连通,再开始前端联调。

## 八、不允许前端做的事(协作红线)

- ❌ 不改后端代码
- ❌ 不改 Prisma schema、不碰数据库
- ❌ 不自己发明接口字段(字段以本文档第六节和后端《接口说明》为准,有疑问先问)
- ❌ 不绕过 token(所有需要登录的接口都要带 token)
- ❌ 不在代码里写死真实客户数据(测试用假数据)
- ❌ 不把测试账号、后端地址外传给任何其他人
- ❌ 不直接接触客户(对接客户由主理人负责)

## 九、验收标准(做成什么算合格)

1. **登录页**:输入测试账号能登录成功,token 被保存,跳转到列表页;错密码有明确提示。
2. **填单页**:能填完表单提交,提交成功有提示,数据真的进了后端(主理人能在后端查到这条客户)。
3. **列表页**:能显示所有客户;能按分层筛选;能按公司名搜索;点客户能进详情。
4. **详情页**:能显示某客户完整信息;有编辑入口。
5. **编辑页**:能修改字段并保存成功,返回详情看到更新后的值。
6. **token 机制**:未登录访问受限页面会跳登录页;token 失效会跳登录页。
7. 5 个页面之间跳转顺畅,无明显报错;能在微信开发者工具里正常预览。

## 十、有问题怎么办

- 接口字段/返回格式不清楚 → 看后端给的《接口说明》,还不清楚问主理人。
- 联调连不上 → 先用上面的 curl 自测后端通不通,再排查是不是代理/地址问题。
- 需求不确定(比如某字段要不要、某交互怎么做)→ **先问主理人,不要自己猜着改**。
- 每做完一个页面,跟主理人同步一下,一起看效果,确认 OK 再做下一个。
