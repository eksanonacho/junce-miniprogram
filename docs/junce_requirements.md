# 君册财税 内部管理系统 — 需求规格说明（PRD）

> 本文档供 Claude Code 直接使用，作为开发输入。
> 系统定位：财税服务公司的内部管理系统（OA + 轻量 CRM + 绩效考核 + 财务核算）。
> 终端：移动端优先（员工手机操作），管理端看板兼容 PC。
> 技术栈建议：见文末「技术约束」。

---

## 1. 系统概述

### 1.1 业务背景
君册财税是一家财税服务公司，按 SOP 管理「客户从入库到出库」的全生命周期。
公司分三大部门：**商务部、业务部、会计部**，外加 **总务** 与 **老板（纪姐）** 两个管理角色。

### 1.2 系统目标
- 客户全生命周期可追踪（线索 → 签单 → 服务 → 出库）
- 各岗位工作流转、交接、审批线上化
- 员工考核可量化、可追溯
- 费用与利润可自动核算
- 管理层可通过看板实时监管

### 1.3 角色清单（RBAC）
| 角色 | 说明 | 主要权限 |
|---|---|---|
| 商务岗 | 客户线索、洽谈、签单、信息披露 | 录入客户、提交费用、发起指派 |
| 业务岗 | 业务专员 / 外勤，办理具体业务 | 接收任务、更新业务进度、确认考核 |
| 会计岗 | 记账、报税等周期性服务 | 接收任务、更新服务进度、确认考核 |
| 部门主管 | 各部门负责人 | 任务下放、进度跟踪、星级评分、部门看板 |
| 总务 | 公司总务，核算与协调中枢 | 审核费用、成本核算、利润核算、汇总邀约 |
| 老板(纪姐) | 最高管理者 | 审批、全局看板、风险提报查看 |

## 3. 核心业务流程（Workflow）

### 3.1 客户入库流程
```
商务岗录入成交客户信息披露
  → 填写: 客户画像 + 成交业务类型(单次/托管) + 套餐类型 + 注意事项
  → 提交
  → 系统按业务类型自动建议指派:
       单次业务   → 指派 业务岗
       一站式托管 → 指派 业务岗 + 会计部
  → 进入下一环节(费用流转)
```

### 3.2 费用流转与总务审核（关键卡点）
```
商务岗发起费用模块: 收费类型(已收/待收) + 金额 + 合同 + 发票
  → 【单独发起，指令发送给总务】
  → 总务查收、阅读
  → 总务确认后，方可进入业务岗 / 会计岗的交接
  ⚠ 硬规则: 总务未确认前，业务/会计岗看不到该客户交接任务
```

### 3.3 业务岗 / 会计岗服务流程
```
接收交接任务
  → 阅读岗位要求(阅读版，需确认)
  → 办理业务 / 周期性服务
  → 更新进度
会计岗周期性服务包含: 档案/开票/记账/报税/年报/社保公积金/银行托管
```

### 3.4 考核流转（场景化）
```
场景: 工作中发现问题(办件错误 / 开票错误 / 错报等)
  → 负责人发起考核 / 发起制度阅读要求
  → 被考核人收到提醒
  → 被考核人阅读制度 + 签字确认
  → 计入考核一次(count +1)
  ⚠ 每发起一次 = 计入考核一次
```

### 3.5 主管任务流程
```
对下属:
  发布 月/日任务 → 设置完成时限 → 发送提醒
  → 下属完成 → 主管对结果星级打分(1-5星) + 文字反馈

对部门:
  发起任务下放 → 跟踪进度
  例: 成交后发起业务部任务，业务进度权限同步给「会计部负责人」+「客户主理人」

对上(看板):
  一张看板看清一周内:
    客户服务达成率 / 业绩达成率 / 新增户手续进度 /
    托管户业务增减进度 / 客户裂变业务咨询
```

### 3.6 总务核算流程（最复杂）
```
单笔:
  接收 客资提报 + 费用提报 + 套餐匹配 → 进入总工作台
  → 核算经手各岗位成本
  → 每单服务闭环后，自动生成单笔利润核算
  → 向纪姐发起提报 → 纪姐审批 → 方可进入管理中心

周度:
  发起各部门负责人汇总邀约:
    商务部: 核对成交客户(交接进度 / 发票+金额+合同三流一致 / 周内沟通反馈 / 服务考核)
    业务部: 核对业务进度 + 考核进度
    会计部: 核对服务进度 + 业务进度 + 考核进度 + 沟通事务

月度:
  发起 君册收支核算 + 经营看板 + 风险提报
  → 提报纪姐 → 纪姐阅读审批 + 给建议
```

## 6. 技术约束

```
前端(移动端): uni-app (Vue3) —— 一套代码可发布微信小程序 + H5
管理端看板:   可用同一套 uni-app 的 H5 端，或 Vue3 + Element Plus 后台
后端:         Node.js (NestJS) 或 Python (FastAPI)
数据库:       PostgreSQL / MySQL
权限:         RBAC，基于角色的菜单与数据权限
部署:         Docker，与现有 AI 初诊项目共用服务器(不同容器隔离)
认证:         JWT
开源模板:     如需套用后台模板，只选 MIT / Apache-2.0 协议，禁用 GPL
```

## 7. 关键业务规则（硬约束，开发必须遵守）
1. 费用未经总务审核，业务/会计岗不可见对应客户交接任务。
2. 利润核算必须经纪姐审批后，才进入管理中心。
3. 考核每发起一次，计入考核次数 +1，且需被考核人签字确认。
4. 业务进度更新后，权限同步给：会计部负责人 + 客户主理人。
5. 所有金额相关计算（费用、成本、利润）需保留两位小数，避免浮点误差（用 decimal）。
6. 客户分层四档固定：VIP / 优质 / 中低部 / 0申报。

- 客户财税数据加密存储（AES-256）
- 传输 HTTPS
- 操作日志可追溯（谁在什么时间改了什么）
- 角色越权访问拦截
