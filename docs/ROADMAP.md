## 总原则

1. **先后端核心链路,再前端页面。** 后端接口稳定了,前端才有得对接。
2. **先让数据流跑通(填单→办件→托管→任务),再做统计展示(看板)。**
3. **一次只做 1-2 个模块**,做完 curl 验证通过,再下一个。
4. 涉及客户未提供资料的模块,先搭框架、留 TODO,不自己编规则。

## ⏭ 下一阶段(可立即开发,不阻塞)

### 模块 2:办件流转 + 办结打卡
- 目标:业务链路第二步。客户的服务项 → 提交办件 → 办结 → 回小程序打卡 → 上传电子材料归档 → 交接下一步
- 涉及页面:pages/workorder/(我的办件 / 办结打卡)
- 涉及接口:办件创建、状态更新、打卡、文件上传归档、回执接收人设置
- 涉及表:**新建** ServiceItem(服务项)、WorkOrder(办件)
- 依赖:模块 1 客户(已完成)
- 客户资料:基本够,办结上传的材料类型待细化(可先做通用上传)

### 模块 3:费用提报 + 总务审核
- 目标:商务提报费用 → 总务审核(已收/未收)→ 未收时总务向主理人发起催收 → 审核通过才进入交接
- 涉及页面:pages/charge/(费用提报 / 总务审核台)
- 涉及接口:费用创建、总务审核、催收发起
- 涉及表:**新建** Charge(收费)
- 依赖:模块 1 客户(已完成)
- **硬约束**:所有费用/合同/发票接口权限限总务 + 管理员
- 客户资料:费用字段待细化(可先用已知字段:托管费/一次性/第三方/人工成本)

> 模块 2 和模块 3 **可以并行**(分属办件和费用两条线,数据上独立)。

## ⏭ 后续阶段(依赖前序模块)

### 模块 4:财务岗托管入档(仅代理户)
- 目标:业务链路第三步。从业务组接收代理档案 → 托管入档登记 → 服务方案匹配(需主理人确认)→ 分派会计(需分派会计确认)
- 涉及页面:pages/tenant/
- 涉及接口:托管登记、方案确认、分派确认
- 涉及表:**新建** TenantRegister
- 依赖:模块 1 客户 + 模块 2 办件(代理户要先走完办件)

### 模块 5:任务发布 + 确认
- 目标:业务链路第四步。主管发布月度计划 → 会计确认 → 主管按节点发起具体任务、设时效 → 会计完成确认
- 涉及页面:pages/task/(任务发布 / 任务列表 / 进度跟踪评分)
- 涉及接口:任务创建、确认、完成、评分
- 涉及表:**新建** Task
- 依赖:角色系统(已完成)
- **阻塞**:第四步"具体任务1/2/3"内容客户正在编写,任务框架可先做,任务内容等资料

### 模块 6:业务裂变(简化版)
- 目标:代理户裂变,分派会计/主管向主理人填单(含价格、指派人)→ 确认 → 归档。**不做群协同。**
- 涉及页面:pages/fission/
- 涉及接口:裂变填单、确认、归档
- 涉及表:**新建** Fission
- 依赖:模块 1 客户 + 模块 5 任务体系

## ⏭ 最后阶段:看板(需前序模块的数据)

### 模块 7:看板系统
- 目标:5 个看板
  - 服务看板、老板看板、客户看板:**自动统计**前面模块产生的业务数据
  - 经营看板、工资看板:**手动录入 + 自动汇总**(加减乘除、汇总、可视化),不做自动反推
- 涉及页面:pages/dashboard/(5 个看板 + 2 个录入页)
- 涉及接口:统计查询接口、经营/工资数据录入接口
- 涉及表:经营/工资录入数据表
- 依赖:**前面所有业务模块**(有了数据才统计得出来)。这是为什么看板放最后。

## 施工依赖关系总结

```
模块0 地基(✅) → 模块1 客户(✅)
                      ├─→ 模块2 办件 ┐(可与模块3并行)
                      ├─→ 模块3 费用 ┘
                      │      └─→ 模块4 托管(需办件)
                      ├─→ 模块5 任务(需角色,任务内容等资料)
                      │      └─→ 模块6 裂变(需任务)
                      └─────────────→ 模块7 看板(需前面所有模块数据)
```

### 关键判断
- **可并行**:模块 2(办件)和模块 3(费用)数据独立,可同时开发。前端页面也可分给不同人。
- **必须等客户资料**:模块 5 任务内容(等会计任务)、分层判断(等分层标准)、细粒度权限(等权限表)。
- **必须等前序模块**:模块 4 等模块 2;模块 6 等模块 5;模块 7 等几乎所有模块。

### 前后端协作建议
- 后端(主理人)按上述顺序逐模块做接口 → 每个模块出"接口说明" → 交给前端同学做对应页面。
- 同学负责相对独立、不碰核心的前端页面(客户页、裂变页、看板展示页、经营/工资录入页)。
- 核心(权限、客户主流程、费用审核)由主理人掌握。
